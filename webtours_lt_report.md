По пропускной способности регрессии **нет**. Запас относительно SLA 3 с — **существенный** (p95 &lt; 0,25 с на большинстве шагов).

## 2. Риски при установке релиза на промышленную среду

### 2.1. Риск — **низкий** (задержки)

Рост p95 времени ответа на 1090 в пределах ~15% при сохранении выполнения SLA 3 с. Операции сценария низколатентные; риск нарушения пользовательского SLA при профиле 3000 оп/ч — **низкий**.

**Риск принят.**  
**Предлагаемое действие:** зафиксировать мониторинг p95/p99 на шагах `Login` и `ByTickets` в Grafana после выката.

### 2.2. Риск — **низкий** (стабильность)

Ошибок HTTP и падений проверок нет на обеих версиях.

### 2.3. Риск — **средний** (достижение целевого профиля 3000 оп/ч)

Фактическая интенсивность за 32-минутный прогон — **~2670** полных итераций/ч (1424 за 32 мин), при целевых **3000** оп/ч. Система успевает обрабатывать почти целевой поток; для подтверждения потолка 3000 оп/ч рекомендуется отдельный тест на поиск максимальной производительности (ступенчатое повышение нагрузки).

**Предлагаемое действие:** при необходимости — тест «на отказ» с увеличением `JOURNEYS_PER_HOUR` и длительным плато.

## 4. Ограничения тестирования

1. Протестирован один скриптовый бизнес-процесс: вход → поиск/бронирование рейса → покупка билета → выход.
2. Использованы учётные данные по умолчанию (`bilbo` / `riddle`).
3. Не проводилось тестирование отказоустойчивости и длительной стабильности (soak).
4. Длительность прогона 32 мин с плато 25 мин; экстраполяция на полный час даёт ~2670 оп/ч, а не полные 3000 за 60 мин плато.
5. Мониторинг инфраструктуры — по внешнему дашборду Grafana; детальный разбор утилизации CPU/RAM в отчёт не включён (рекомендуется приложить скриншоты при сдаче).
